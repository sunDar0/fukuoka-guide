# 가이드 UI/UX 점검·개선

빌드 없는 정적 사이트라 화면 확인 수단은 브라우저 실측뿐이다. 그래서 이 스킬은 "어떻게 재현하고, 어디까지 고치고, 무엇으로 확인하는가" 를 정한다.

## 대상 구조

| 화면 | 파일 | 렌더링·이벤트 코드 |
|--|--|--|
| 플래너 | `index.html` | `planner.js` 의 `render*` 함수, 입력·공유·초기화 핸들러, `setupSectionNav` |
| 지도 | `map.html` | `map.js` 전체 (Leaflet 지도·마커 클러스터·필터·검색·경로·레이어·바텀시트) |
| 공통 | `style.css` | 다크 테마, 반응형 구간 1024/768/480/360px |
| 오프라인 | `sw.js` | 캐시 우선 전략, `CACHE_NAME` |

데이터 값(`data.js`, `planner.js` 상단 기본 데이터, `itineraryTemplates`)은 범위 밖이다.

## 실측 절차

1. 프로젝트 루트에서 `python3 -m http.server <포트>` 를 백그라운드로 띄운다.
2. 브라우저 도구(claude-in-chrome)로 새 탭을 열고 페이지를 띄운다. 플래너는 URL 파라미터로 바로 생성할 수 있다: `index.html?s=2027-07-10&e=2027-07-13&a=2&c=1&i=1`.
3. **서비스 워커 캐시부터 확인한다.** `sw.js` 는 캐시 우선이라, 파일을 고쳐도 옛 파일이 보일 수 있다. `caches.keys()` 와 캐시 안 파일 내용을 확인하고, 옛 버전이면 탭을 모두 닫고 다시 열어 새 서비스 워커를 활성화한다. 이걸 건너뛰면 고친 결과를 못 보고 "안 고쳐졌다" 로 잘못 판정한다.
4. 상태 확인은 스크린샷보다 `javascript_tool` 로 값을 읽는 쪽을 먼저 쓴다(예: `Chart.getChart(canvas)`, `routeNumberMarkers.length`, `getComputedStyle(el).transform`). 값이 결론의 근거가 된다. 시각 문제(겹침·잘림·경계 줄)만 스크린샷으로 본다.
5. 모바일 폭은 `resize_window` 로 맞추고, `innerWidth` 를 읽어 실제로 바뀌었는지 확인한다. 안 바뀌면 그 사실과 대체 방법을 기록한다.
6. 끝나면 탭을 닫고 서버를 끈다.

## 점검 관점

사용자 상황에서 순서대로 본다.

- **닿는가**: 원하는 정보(명소 상세, 일차 일정, 경비)까지 몇 번 조작이 필요한가. 모바일에서 지도와 시트가 서로 가리지 않는가.
- **상태가 맞는가**: 필터·검색·레이어·경로처럼 상태를 바꾸는 조작 뒤에 화면의 모든 부분이 같은 상태를 보여주는가. 예전 상태가 남는 곳(경로가 필터 변경 후 남음 등)이 대표적인 결함이다.
- **다시 그려도 되는가**: 같은 화면을 두 번 생성(설정 변경 → 다시 만들기)해도 차트·리스너·DOM 이 정상인가. `innerHTML` 로 다시 그리는 코드는 이전 객체 참조가 남는지 본다.
- **터치로 되는가**: 터치 대상 44px, 드래그와 탭 구분, 가로 스크롤 영역.
- **오프라인·느린 망**: 외부 자원(타일, 마커 아이콘, CDN)이 실패하면 무엇이 보이는가.

## 개선 원칙

- 승인된 항목만 고친다. 고치다가 발견한 것은 `07_ui_changes.md` 의 "부수 발견" 에 적는다.
- 상태 불일치는 상태를 바꾸는 지점(핸들러)에서 함께 정리하는 쪽을 먼저 고려한다. 새 상태 관리 구조를 만들지 않는다.
- 스타일 수정은 기존 반응형 구간 안에 넣는다. 새 구간을 만들기 전에 기존 구간으로 되는지 본다.
- HTML·CSS·JS 를 바꿨으면 `sw.js` 의 `CACHE_NAME` 을 한 번 올린다.

## 검증

1. `node --check map.js && node --check planner.js && node --check data.js && node --check sw.js`
2. 고친 항목마다 점검 때와 같은 재현 절차로 다시 실측해 값이 바뀐 것을 적는다(전·후 값).
3. 고친 화면의 다른 기본 동작이 그대로인지 한 번 훑는다(지도: 마커 클릭·필터·검색, 플래너: 생성·일차 이동·경비 조정).
4. 리더는 개선이 끝나면 맥락을 공유하지 않는 새 `ui-ux-designer` 를 점검 모드로 띄워 같은 항목을 다시 재현시킨다. 같은 세션의 자기 검토는 자기 수정을 옹호하는 쪽으로 기울기 때문이다.
